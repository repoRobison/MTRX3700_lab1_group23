# Piano Tiles FPGA

Clean Quartus Prime Lite 18.1 project for the DE1-SoC.

## Open and compile

1. Open `piano_tiles.qpf` in Quartus.
2. Select the `top_level` revision for the complete game.
3. Run **Processing > Start Compilation**.
4. Program `build/top_level/top_level.sof`.

The alternative `fpga_smoke_test` revision is a deterministic board-level
hardware check. Its programming file is generated under
`build/fpga_smoke_test/`.

## Project structure

```text
Piano_Tiles/
|-- piano_tiles.qpf
|-- top_level.qsf
|-- fpga_smoke_test.qsf
|-- constraints/
|   |-- top_level.sdc
|   +-- fpga_smoke_test.sdc
|-- rtl/
|   |-- common/       shared parameters
|   |-- display/      lesson display, BCD ROM and seven-segment decoding
|   |-- game/         scheduling, lanes, hits, level, score and multiplier
|   |-- input/        synchronisation, debounce and board inputs
|   |-- timing/       BPM and millisecond timing
|   +-- top/          complete-game FPGA top level
|-- smoke_test/       isolated board smoke-test RTL
|-- tb/               simulation-only testbenches
|-- scripts/          test runner
|-- docs/             board pin-assignment reference
+-- build/            generated by Quartus and ignored by Git
```

There are no contributor-named source folders. Empty placeholders, duplicate
lane FSMs, incomplete legacy modules and generated Quartus databases are not
part of this clean copy.

## Main synthesis hierarchy

`top_level` uses:

- `button_input`, `debounce`, and `synchroniser`
- `reaction_time_fsm` for reset, play, level-change and game-over control
- `level_select`
- `beat_gen` and `timer`
- `rng`, `note_scheduler`, and `lane_controller`
- `hit_detector`
- `multiplier` and `score`
- `display`, containing `bcd_encoder_4` and six instances of `seven_seg`

`rtl/common/game_params.svh` is an included parameter header and is therefore
not listed as a separate synthesis unit.

## Reaction Time Game module reuse

All nine lesson-module names are active in the synthesis hierarchy:

| Lesson module | Piano Tiles role |
|---|---|
| `top_level` | DE1-SoC integration boundary |
| `seven_seg` | Six active-low HEX decoders inside `display` |
| `timer` | Millisecond phase timer inside `beat_gen` |
| `debounce` | Four key and three switch conditioners |
| `synchroniser` | Two-flop input synchroniser inside each debouncer |
| `rng` | Ten-bit LFSR sampled by the note scheduler |
| `reaction_time_fsm` | Reset, playing and terminal game-over lifecycle |
| `display` | Lane blanking and six-display ownership |
| `bcd_encoder_4` | Clocked four-digit score conversion ROM |

The assignment allows lesson modules to be adapted. Exact changes and the
reason for each are recorded in `docs/module_reuse.md`.

## Difficulty timing

- Easy: 83 BPM, Come Together - The Beatles
- Medium: 120 BPM, Get Back - The Beatles
- Hard: 120 BPM, with independently scheduled notes allowed to coincide,  Get Back - The Beatles

## Generated files

Quartus will recreate `db/`, `incremental_db/`, and `build/` during
compilation. They are intentionally ignored by Git. Source files, both QSF
revision files, the QPF, and both SDC constraint files must remain tracked.

## Tests

All `*_tb.sv` files are under `tb/` and are excluded from both Quartus
revisions. Each of the nine lesson modules now has direct self-checking coverage;
`system_tb.sv` is the top-level integration test. On a system with Verilator
installed, run:

```sh
sh scripts/run_all_tests.sh
```

Quartus Prime Lite 18.1's bundled ModelSim-Altera can run the same suite on
Windows when Verilator is unavailable:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_all_tests_modelsim.ps1
```

Pin assignments and the Cyclone V device selection are preserved from the
working project. No pin assignment was guessed or changed during cleanup.
